## 权限修复

根因：SDK 内部已识别本地 ParticipantInfo 和权限，公共回调丢弃了这些字段；设备因而不知道既有房间的发布权限已改变，启用麦克风后仍保持旧的接收图。

公共 SDK 提供本地身份和权限快照；固件将变化作为失效通知，先关闭当前会话音频，再读取经过认证的 Owner 配置并重建连接。LiveKit 权限本身不授权打开麦克风。失败使用已有连接退避重试，通知不占命令 FIFO，不给板子或 Host 添加单独补丁。

本地 SDK 提交 `f7b4279643451c43d0bc0017ac1f564971de6714`。公共权限转换、observer 边界、输出策略、连接退避及真实 FreeRTOS/QEMU 队列压力测试通过。BOX-3 连续 360 秒日志中，禁麦通知发生在 76.09 秒，MicCap 76.53 秒停止，80.54 秒重返 READY；开启通知发生在 237.60 秒，240.82 秒 MicCap 启动，242.05 秒重返 READY。期间没有复位。服务端分别确认禁麦后 can_publish=false/无音轨、恢复后 can_publish=true/麦克风音轨。原设置已恢复开启。开启后的空闲 SRAM 约 32 KB，禁麦后约 63 KB，无本轮持续泄漏证据。该测试使用 c41956d6a+dirty + f7b4279，不作为正式基线通过率。
